## Comments

**2026-11-09 — owner decision (Han), Q9/Q19.**

**2026-11-11 — owner decisions (Han), on the Draft PR's open choices:**
- **Q49:** each Pomodoro Session stores the Mac's UTC offset (seconds east of UTC) when it starts, and days and shown times use that stored offset, so travelling never moves past sessions. Done in schema v23 (`pomodoro_sessions.utc_offset_seconds`, CHECK within ±18 h); the shell reads it with each clock reading (`Moment::utc_offset_seconds`, `localtime_r`) and a focus keeps the one of its start.
- **Q50:** a Stopped session shows its actual focus before Stop, "Stopped after 12 min". Schema v23 adds `stopped_after_seconds` (Stopped only, 0 to the planned length): the planned length minus what the timer showed as left, on the awake clock (`Instant`), so sleep never counts.
- **Q51:** the sidebar row is named "Pomodoro", like the page heading; the ⌘K command is "Pomodoro" too.
- **Q52:** within a day, sessions are listed oldest first (a day log); days stay newest first.

**2026-11-11 — implementation notes (AI), Draft PR:**
- Schema v23 (forward-only, `pomodoro::migrate_v23`): `ALTER TABLE pomodoro_sessions ADD COLUMN utc_offset_seconds INTEGER CHECK (BETWEEN -64800 AND 64800)` and `ADD COLUMN stopped_after_seconds INTEGER CHECK (NULL OR (outcome = 'stopped' AND BETWEEN 0 AND planned_seconds))`. The core requires both on every new session (`EndedSession::check`). Rows stored before v23 keep NULL in both (choice, say if you prefer otherwise): the table is append-only (its UPDATE trigger stays), and filling in the migration's current offset would be a guess no better than the one made when reading — reading puts a NULL-offset session on the reading Mac's zone at its own start, which also gets each old session's daylight-saving side right. Only test and dev data are on v22; the owner's real store is still v15.
- Sessions hold no user text; the history reads the Task's title only while the Task is shown (`task_visible`). Task titles go to AI interfaces like everywhere else (Tasks are never Exclude from AI, ADR 0004).
- Paging bound: going back in time, a session's local date can now step forward by up to two days (offsets within ±18 h, a flight or a zone change across the date line), so the page looks two days ahead before it closes; `paging_never_misses_a_session_whose_clock_was_two_days_ahead` fails with one.
- The shell's Pomodoro event carries `sessionStored`, so the page reads again only when a session was stored, not on the one-second ticks. Load more appends the core's page as it comes: the cursor starts after the last day shown and a read from the top drops an older answer, so no day can come twice (the old de-duplication was dead code).
- CLI and MCP sessions carry minutes only (the seconds repeated them) plus `utc_offset_seconds` and `stopped_after_minutes`. MCP pages a week by default and caps an answer at 100 sessions in whole days (`PomodoroHistoryPage::capped`, its first day always whole); the CLI keeps 50 days.
- Choices made without the owner (say if you prefer otherwise): (1) the day total is the **sum of the minutes each session shows** (25 + 7, rounded per session like the Progress Entry), so the numbers on the page add up; the unrounded seconds can differ by under a minute per session. (2) The day line also says "· 1 stopped" when there were Stopped sessions. (3) A Stopped row keeps "25 min planned" as its length and says "Stopped after 12 min" as its outcome; under half a minute it says "Stopped after <1 min", and a session from before v23 just "Stopped". The outcome column now sizes to its text, and a day's rows share one grid (CSS subgrid) so they line up.
- Known limit: a session whose Task no longer existed when it was stored (restored away, Ticket 02) has no Task id, so it shows "No Task", not "Task removed".
- Still open: the look of the page in the real app window with synthetic data (the screen awake).
