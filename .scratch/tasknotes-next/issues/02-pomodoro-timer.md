# 02: Pomodoro timer with notifications and Overtime

**What to build:** A Pomodoro timer, optionally for one Task, that keeps running with the window closed (spec stories 16–20, 22; stories 17–19 as revised 2026-11-10).

**Blocked by:** None

**Status:** ready-for-agent

**Implementation:** in progress — Draft PR

## Acceptance criteria

- [x] Durations default to 25 / 5 / 15 (long break after every 4 sessions) and are adjustable and remembered. _Evidence: `PomodoroDurations::default()` and `DurationLimits::CURRENT` (focus 1–180, breaks 1–60, long break after 1–12; the one source for the check, the refusal text and the window's limits) in `crates/tasknotes-core/src/pomodoro.rs` (`defaults_are_25_5_15_with_a_long_break_after_4`, `durations_outside_the_limits_are_refused`, `the_limits_the_window_shows_are_the_ones_checked`, `every_fourth_finished_session_earns_a_long_break`, `stopped_sessions_do_not_count_toward_the_long_break`, `adjusted_durations_apply_from_the_next_focus`). Kept in `shell-settings.json` beside the database (`shell_settings.rs` round-trip; `shell_state.rs` `pomodoro_lengths_are_checked_saved_and_remembered`, failed save changes nothing). Settings › Pomodoro: `src/pomodoro.test.tsx` shows 25/5/15/4, saves 50, refuses out-of-range values against the limits the shell sends (no copy in TypeScript)._
- [ ] A session can be started with or without a Task; the menu bar shows time left while running and the running Overtime ("🍅 +07:12") after the planned end until the owner responds; "☕ Done" after a break until the owner responds. _Evidence (logic): start with no Task or an unfinished one, open Task offered first (`src/pomodoro.test.tsx`); menu bar text from the core timer: "🍅 25:00", "🍅 12:34", rounded-up "🍅 00:01", "🍅 +07:12" (`a_focus_counts_down_and_runs_into_overtime_at_its_end`), "☕ Done" held until a click (`every_switch_waits_for_a_click`). The window shows the seconds the shell sends and has no clock of its own (`shows only what the shell sends, with no clock of its own`). The session's own title-only menu-bar item exists while the timer is not Idle (or a session waits to be stored), whatever Keep in menu bar says, and closing the window then hides it (`close_action` tests). **Open: native check that the item and its titles show in the real menu bar with the window closed, and that "Count +07:12" updates in the open menu.**_
- [ ] The focus end and the break end each deliver one macOS notification, silent when the Pomodoro's own Silent setting is on; the focus end offers Start break and Count overtime, the break end Start focus; every switch waits for a click. _Evidence (logic): one notice per end through the `Step` seam (`pomodoro_state.rs` `the_focus_end_sends_exactly_one_notification`, `the_break_end_sends_one_notification_offering_the_next_focus`, `silent_notifications_follow_the_pomodoro_setting_alone`); Silent saved and remembered (`silent_pomodoro_notifications_are_saved_and_remembered`) and independent of interaction sounds (`has a Silent setting of its own…`). Notifications are numbered: a click on an older or unreadable one changes nothing (`a_click_on_an_older_or_unreadable_notification_changes_nothing`); answering from the menu bar or window withdraws the delivered one (`answering_from_the_menu_bar_or_the_window_withdraws_the_notification`). tauri-plugin-notification 2.8.0 shows desktop actions (macOS puts two in an Options menu; a click on the notification opens the window). **Open: native check of delivery, sound and Silent, the Options menu, both notifications' actions and the withdrawal.**_
- [x] At the planned end, Start break counts no Overtime; "Count +07:12" counts the Overtime up to the click, records the session Finished with it and starts the break in one click; Stop after the planned end is Finished without Overtime. _Evidence: core `start_break_does_not_count_the_overtime` (10 min late → 0), `count_overtime_counts_up_to_the_click_and_starts_the_break_at_once` (7 min 12 s stored, break started), `overtime_is_counted_even_when_the_tick_had_not_run_yet`, `stopping_after_the_planned_end_finishes_without_overtime`, `stopping_before_the_planned_end_is_stopped`; shell `count_overtime_stores_it_and_starts_the_break_in_one_click`; window `shows the running Overtime at the planned end and offers Start break or Count it`._
- [x] Sleep never counts as focus, break or Overtime. _Evidence: lengths run on an awake clock (`Moment { wall, awake }`); core `sleep_never_counts_as_focus` (2 h asleep 10 min in: still 15:00 left, end 25 awake minutes in, stored on the wall clock), `sleep_never_counts_as_overtime_or_break`. The shell's awake clock is `std::time::Instant`, measured on the owner's Mac to stop during sleep (see Comments)._
- [x] Quitting during a session saves it: Stopped before the planned end, Finished without Overtime after it. _Evidence: `pomodoro_state.rs` `quitting_saves_what_runs` (and the unsaved ones are tried once more); `save_on_quit` runs on `RunEvent::Exit`, which every way of quitting reaches._
- [x] A finished session tied to a Task adds one Progress Entry ("Pomodoro: 25 min focus", "Pomodoro: 25 + 7 min focus" only when Overtime was counted) and never changes status; a Stopped session adds none. A session whose Task is gone is kept without it; any other failure to store is shown and kept to try again. _Evidence: `crates/tasknotes-core/tests/pomodoro.rs`: In Progress stays In Progress at 40% with note "Pomodoro: 25 + 7 min focus"; Ready stays Ready ("Pomodoro: 25 min focus"); a Task Completed mid-session stays Completed; Stopped adds none; a Task in Removed keeps the session without an entry; `a_session_whose_task_is_gone_after_a_restore_is_kept_without_it`; one transaction with `task.progress` and `pomodoro.record` Audit Entries. Shell `a_session_that_could_not_be_stored_is_kept_shown_and_stored_again` ("⚠️ ☕ 04:00", "⚠️ Not saved", Try again / Discard in the menu), `an_unsaved_session_is_dropped_only_when_the_person_discards_it`; window `keeps a session that could not be saved on screen…`. The window re-reads Tasks when the shell reports the change._
- [ ] On first use, if the notification style is not Persistent, a one-time tip opens the Tasknotes page in System Settings; the exact macOS label is verified on the owner's Mac. _Evidence (logic): the alert style is read with `UNUserNotificationCenter` (`macos_notifications.rs`; the plugin does not expose it), only inside a bundled `.app` (elsewhere it returns unknown instead of crashing; tested). Due once unless Persistent, unknown counts as not Persistent, remembered across restarts (`the_notification_tip_is_due_once_unless_the_style_is_persistent`); button opens `x-apple.systempreferences:com.apple.Notifications-Settings.extension?id=store.adamaja.tasknotes`; `src/pomodoro.test.tsx` first start shows it, second does not ask. **Open: native check of the style read (it reads the UN center while the plugin posts through NSUserNotificationCenter; see Comments), the link and the macOS label.**_
- [x] Sessions are stored in the core with start, planned length, Overtime, outcome (finished / stopped) and optional Task. _Evidence: schema v22 `pomodoro_sessions` (append-only triggers, CHECKs: Stopped has no Overtime, end ≥ start); `record_pomodoro_session` (desktop only) and `list_pomodoro_sessions(from, to)` / `get_pomodoro_session` for Ticket 14 (readable by every interface). `tests/pomodoro.rs` 14 tests incl. refusal of impossible sessions, rewrite attempts, v19 → v22 upgrade._

**2026-11-10 — review fixes and the decisions above (AI), Draft PR #34:**
- Core: `Moment { wall, awake }` on every timer step; lengths on the awake clock, stored times on the wall clock. `TimerState` hands the window remaining/Overtime seconds; `DurationLimits::CURRENT` is the only copy of the limits (the refusal text is built from the same constants). `next_change_in` tells the shell when the shown time next changes. A session whose Task no longer exists (e.g. restored away) is stored with `task_id` NULL instead of being refused.
- **Sleep clock (measured, not assumed):** on the owner's Mac (Rust 1.98.1), `std::time::Instant` read 191691.778 s, equal to `clock_gettime(CLOCK_UPTIME_RAW)`, while `CLOCK_MONOTONIC_RAW` read 201465.800 s; the 9774 s gap is the time slept since boot (`pmset -g log` shows the sleeps). So `Instant` does not advance during sleep and is the awake clock; no sleep/wake listener is needed. A few seconds of Power Nap dark wake may count (CLOCK_UPTIME_RAW runs then).
- **Notification path (read from the sources in `~/.cargo/registry`):** tauri-plugin-notification 2.8.0 posts through notify-rust 4.19 without `preview-macos-un`, i.e. mac-notification-sys and the deprecated `NSUserNotificationCenter`; its `remove_active` does nothing on macOS. The alert-style read uses `UNUserNotificationCenter`. Both act on the app's one entry in System Settings › Notifications, so the read should match, but that is unverified until the native check. Switching the posting to UN was not done: the plugin has no such option (only notify-rust's preview feature, whose `mac-usernotifications` crate is not in the lockfile), UN needs an authorization request the plugin does not make on desktop, and it ends a process that is not in an app bundle (development runs). Instead `macos_notifications::withdraw_delivered` removes delivered "Focus done" / "Break over" notifications through `NSUserNotificationCenter` (main thread) when the owner answers anywhere, the timer moves past them, at quit and at launch. Stale clicks are harmless anyway: each notification carries its number and a click on an older one changes nothing.
- **Threads:** the plugin keeps one thread per notification blocked in `wait_for_response` until it is answered or leaves Notification Center (mac-notification-sys polls every 0.5 s). Withdrawing on every answer ends that thread, so at most one waits at a time (the notification on screen). If withdrawal is impossible (no bundle identifier), a thread lives until the owner clears the notification.
- Shell: every step returns a `Step` (notify, withdraw, sessions to store) carried out with the timer lock released; `pomodoro_command` is `async`, menu clicks run on a blocking task, notification clicks on the plugin's thread, so no SQLite write runs on the main thread or under the lock. A failed store keeps the session, shows the reason in the window (Try again / Discard) and in the menu bar ("⚠️ Not saved"). At quit a failure can only be logged.
- One source for the next Task: the window's Start focus after a break sends `start_next_focus`, the same command as the menu bar and the notification; the shell's `lastTaskId` decides.
- **Idle wakeups:** before, the tick thread woke once a second for the whole life of the app, Idle included (an unconditional `sleep ≈1 s; tick` loop), and the window ran its own 1 s interval while counting. Now the tick thread parks on a condvar while Idle and at "☕ Done" and, while counting, wakes once per shown-second change; the window has no interval and renders what the shell pushes. Measured by `the_tick_thread_sleeps_while_nothing_counts_and_ticks_each_second_while_it_does`: 0 ticks in 1.3 s Idle, 1–3 in 2.1 s counting, 0 after Stop. Process-level idle wakeups (`top -stats idlew`) not measured: that needs the app running.
- Still open: the native checks above (menu bar item and titles with the window closed, live "Count" label, both notifications' delivery, sound and Silent, Options menu and actions, withdrawal, alert-style read and System Settings link, quit saving), with the screen awake and synthetic data.
