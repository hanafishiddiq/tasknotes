## Findings and environment actions

1. **Critical verification gap — native WebView input not accessible:** macOS accessibility exposes the Tasknotes window but not its WebView fields. Coordinate input was refused for safety; do not bypass the restriction. Use a structured manual GUI test driven by the owner with synthetic SQLite, and verify results with `scripts/verify_native_acceptance.py`. Keep actual input automation as a separately scoped tooling investigation.
2. **Missing independent review:** GitHub Copilot Pull Request Reviewer returned *quota reached* for all three PRs; an automated comment is not code review. Do not present existing manual Standards/Spec docs as independent. Obtain another reviewer or a legitimately separate review agent before merge.
3. **Manual QA evidence previously ephemeral:** the prior read-only checker lived under ignored `src-tauri/target/`. A portable versioned checker now lives in `scripts/verify_native_acceptance.py`. Only synthetic data is permitted, and the script rejects ordinary app-data paths.
4. **GUI UX lag without reproducible performance signal:** the user reports severe lag even with one synthetic Task. Added Bug #19 (`needs-triage`) and tied it to Ticket 17 performance and Ticket 18 release quality. Next work should establish a tight, red-capable latency/FPS measurement before guessing a fix.
5. **Manual Progress Note not saved:** the user's real click path persisted state/status/progress and Next Step, but all three journal entries had empty note fields. Re-run this single native scenario before closing Ticket 03's acceptance; do not infer whether this was a missed click or app behavior.

## Corrective engineering outcome — autonomous macOS QA

A dedicated E2E branch `test/native-wdio-e2e` now provides opt-in, **debug-only** embedded WebDriverIO tests for actual native Tasknotes. Two independent synthetic-database E2E repetitions passed, including a complete create/edit/status/priority/progress/Next Step/note flow and process restart with SQLite persistence. The missing manual note was verified in the automated flow without further human clicking.

The hidden WKWebView driver required a scoped DOM `select` change event fallback; record this boundary transparently instead of claiming real OS dropdown mouse automation. Never enable the WebDriver listener in a normal app binary or connect it to a personal database. Manual-only fallback should henceforth be reserved for real visual/audio, pointer-fidelity, or performance acceptance that cannot be covered by native WebDriver.

**Still open:** independent Standards/Spec review for stacked PRs and measured diagnosis of severe visible-native lag (Issue #19). Passing functional E2E tests is not a performance sign-off.
